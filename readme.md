# 预设锁定 · ST-PresetLocks

> 自动切换预设时会滤掉酒馆正则扩展的「重新加载聊天以使正则生效」提示（手动切预设不受影响）。

两件事，都在**角色卡管理界面**里做：

1. 给这张卡绑一个**预设**——同一张卡的所有聊天共用一个预设，切角色时自动换回
2. 给这张卡绑一本**世界书**——随卡自动生效，删卡时可选择一并删除世界书文件

两个绑定都写在**角色卡自己身上**（`data.extensions.presetLocks` / `data.extensions.world`），卡导出、上传、换酒馆时一起走。

中文精简版，基于 [Character Locks v4.0.0](https://github.com/aikohanasaki/SillyTavern-CharacterLocks)（aikohanasaki，AGPL-3.0）重做，只保留角色卡级锁定。

## 安装

解压或复制到酒馆的第三方扩展目录：

```text
SillyTavern/public/scripts/extensions/third-party/ST-PresetLocks/
```

或者从 GitHub 安装：扩展面板 → Install extension → `https://github.com/stttwq/ST-PresetLocks`

重启酒馆，刷新页面。

## 兼容性

在真实运行的 **SillyTavern 1.19.0** 上验证过：卡内写入（`/api/characters/merge-attributes` 返回 200）、面板下拉、切角色自动换预设。

版本差异已适配两处：

- `ctx.characterId` 在 1.19 是字符串（`"40"`），旧版本是数字
- `presetManager.select` 是 jQuery 对象；旧版本可能是选择器字符串

## 怎么用

1. 点左上角 ☰ 打开**角色卡管理界面**
2. 在「标签」下面、「创作者的注释」上面有两行：
   - **🔒 预设锁定**：选一个预设，选完立刻生效并写进这张卡
   - **🌍 世界书锁定（可多选）**：勾一本或多本，勾选顺序就是加载顺序
3. 选完立刻生效，并写进这张卡

之后切到这张卡（任何聊天文件），预设都会自动变成绑定的那个。

## 世界书绑定（可多本）

面板里那行是**复选框列表**，勾几本都行，序号就是加载顺序（1 会写进酒馆原生的 `data.extensions.world`，其余进 `worldBooks` 并在打开卡时同步给酒馆的「角色世界书」`world_info.charLore`）。

因为走的是酒馆自己的**角色世界书**机制，所以：

- 打开/切到这张卡 → 绑定的世界书自动生效，不需要在全局世界书里勾选（可以一本全局都不开）
- **不会污染其他角色**：什么都不全局启用，离开这张卡它就不生效了；切回来又自动恢复
- 左侧列表会标状态：`2 本生效中（序号即加载顺序） · N 本被其他卡共用，删卡时保留`

### 一个坑（已处理）

酒馆模块内部的 `world_info` 和 `extension_settings.world_info` **不是同一个对象**。只写后者，界面上看得见但扫描时根本不生效；只写前者，当下生效但刷新就没了。所以两处都会写。

## 决策条：梗概 + 行动选项（v2.3.1）

输入框上方常驻一条决策条，从**最新一楼**抽取剧情梗概与行动选项；点选项直接填进输入框。

**不改预设、不改正则、不改酒馆配置**，纯读取消息原文。

## 阅读位置锁定（v2.2.6 起，v2.3.0 重做判定）

发消息、生成、流式输出都不会再把视图拽到底部；你翻到哪就停在哪。

- 面板底部：☑ 阅读位置锁定 + 「回到底部」
- 只有你**本来就在底部**、**且 1.5 秒内没有主动操作过**时才跟随
- 切聊天时仍然会自动定位到最新一条

实现方式：把酒馆自己的 `power_user.auto_scroll_chat_to_bottom` 关掉（`scrollChatToBottom()` 的唯一开关），再由本扩展接管跟随。

### v2.3.0 修了「发送后到消息出现之间上滑会被弹回」

根因有三层，缺一不可：

1. 酒馆在 `MESSAGE_SENT` 之后才 `addOneMessage()`，事件与 DOM 插入之间有时间差，旧实现在这段时间里就抢先滚了
2. 旧的"是否在底部"用 40px 距离阈值，上滑 30px 会被判定为"还在底部"
3. `scroll` 事件分不清"用户滚的"和"程序滚的"

现在的做法：

- **方向判定**：`scrollTop` 变小哪怕 1px 就视为离开底部；真正到底（差 < 4px）才恢复
- **用户意图锁**：`wheel` / `touchmove` / `keydown` / 在聊天区 `mousedown` 打时间戳，1.5 秒内禁止任何自动滚动
- **按 DOM 插入触发**：`MutationObserver` 观察 `#chat` 子节点变化，在"消息真正出现"那一刻判断
- **流式跟随**：`GENERATION_STARTED` 期间每 250ms 一次轻量检查，用户一上滑立即停

实测（军训14天，`#chat` 可滚动约 11372px）：

| 场景 | 结果 |
| --- | --- |
| 在底部，新消息出现 | 跟到新底部 ✅ |
| 上滑 25px 后新消息出现 | **不动** ✅（旧实现会弹回） |
| 点发送 → 150ms 后上滑 800px → 消息出现 | **停在 10348，内容增长到 11252 也不动** ✅ |
| 上滑后等 1.8 秒（意图锁过期）再插消息 | 仍不动 ✅ |
| 手动滚回真正底部，1.7 秒后插消息 | 正常跟随 ✅ |
| 生成中（流式）在底部 | 逐段跟随 ✅ |
| 生成中上滑 | 立即停止跟随 ✅ |
| 生结束后 | 仍停在你的位置 ✅ |

## 默认值（v2.0.6 起）

| 设置 | 默认 | 理由 |
| --- | --- | --- |
| 切换角色时 | **直接换成记录的预设** | 自动切换就是这套东西的意义 |
| 显示提示 | **关** | 切换应当无感；状态在同面板摘要里能看到 |
| 切换后重绘旧消息 | **开** | 实测：聊天已在屏幕上时，不重绘就是旧渲染 |
| 删卡时一并删世界书 | **开**（仍会弹确认） | 避免残留僵尸世界书；误删前有确认 |
| 绑定预设时自动拍提示词快照 | **是** | 不同卡锁不同提示词开关的前提；否则只是空绑定 |

旧版本升级时会自动迁移一次（只改一次，不会覆盖你后来手改的值）。

## API 连接锁定（v2.2 起）

酒馆里切预设会连带改掉 **API 连接**（来源 / 地址 / 模型 / 代理 / 密钥入口），这就是「配置莫名其妙被吞」的来源。

现在可以把连接一起记到卡上：

- 面板里勾 **API 连接** → 立刻拍一份连接快照（只含酒馆标记为连接类的字段）
- 之后进这张卡会自动把连接拉回快照
- **任何预设切换（包括你手动在下拉里切）都会把连接拉回快照** —— 只有两种东西能改它：这个扩展（「更新连接」按钮）和你手动改 API 设置

实测（你的实例）：

| 步骤 | chat_completion_source | custom_url | custom_model |
| --- | --- | --- | --- |
| 锁定后 | deepseek | discovery-api… | Atria-Dawn |
| 模拟被吞（改成 openai / 清空 URL 与模型） | openai | (空) | (空) |
| 手动切到另一个预设 | **deepseek** | **discovery-api…** | **Atria-Dawn** |
| 手动在 UI 改成 claude（不切预设） | claude（允许，不被拉回） | — | — |

快照字段来自酒馆自己的 settingsToUpdate[...][3] === true（当前 56 项），不靠猜。

## 锁定模型（v2.0 起）

一张卡 = 一个主预设 + 几个可选项。面板默认收起，只留一行摘要；未绑定的卡会自动展开。

```
🔒 锁定   v2.0.2                    卡内          ⌄
主预设「夏瑶 天琴座 V2 Beta 1.0」· 提示词 172/215 · 世界书 2 本
```

展开后只有三项：

1. **主预设**（必选）——列的是当前 API 可用的预设
2. ☐ **提示词启用状态与顺序**——勾上时自动拍快照；之后随时点「用当前状态更新快照」刷新
3. ☐ **世界书**——勾上后出现管理区：序号 + ↑↓ 排序 + × 移除，下面搜索框点一下添加

存在卡上：

```json
{
  "preset": "主预设名",
  "enable": { "prompts": true, "worlds": true },
  "prompts": [ { "character_id": 100001, "order": [ {"identifier":"main","enabled":true}, … ] } ]
}
```

所以**同一个主预设、不同卡也能锁不同的提示词开关与顺序**（快照存在各自的卡上，互不干扰）。

注：上下文模板 / 指令模板 / 系统提示 / 推理格式四个下拉已在 1.9 移除（用不到，且和提示词快照重复占地方）。

注：换了绑定后，酒馆会缓存已经加载过的世界书条目，**注入顺序要重新进一次对话才完全生效**（世界书数据本身不需要刷新页面）。

### 「词 37/52」是什么意思

- **52** = 酒馆 prompt_order 里的**槽位总数**：包含 main、worldInfoBefore/After、charDescription、charPersonality、scenario、chatHistory、jailbreak、personaDescription 等系统槽位，加上你自建的提示词
- **37** = 其中处于启用状态的条数
- 你在提示词管理器里看到的「19 条」是这个预设实际的条目数；两者不同很正常（系统槽位不计入那一栏）

面板现在会直接告诉你快照跟预设是否一致：

`
快照 37/52 ≠ 预设 19/19      ← 快照是旧的，点「更新快照」n快照 19/19 · 22:21            ← 已更新，后面是存储时间n`

> v2.2.4 修正：快照改为取「预设定义」而不是活状态。旧实现会读到扩展自己回写的值，导致怎么点「更新快照」数字都不变。
> v2.2.5：如果你在酒馆提示词管理器里手动改过开关/顺序，再点「更新快照」会取**你的改动**（而不是预设定义），所以同一预设下不同卡仍可各锁一套。

### 注入顺序（实测）

用三本各带唯一常驻条目的世界书做过对比（拦截请求、0 额度）：

| 绑定序号 | 实际注入位置 |
| --- | --- |
| 序号 1 | **最后**（它是 ST 原生字段 `data.extensions.world`，酒馆固定把它排在最后） |
| 序号 2、3、4… | 按序号从前到后 |

酒馆组装时会把它自己的额外书列表再倒一次，所以本扩展存 `charLore` 时先倒序存（`slice(1).reverse()`），注入后刚好回到界面序号。实测绑定 `[GAMMA, ALPHA, BETA]` 时注入顺序为 `ALPHA(#2) → BETA(#3) → GAMMA(#1)`。

只绑定一本时，另两本**不会**混进来（已验证 `AAA:true, BBB:false, CCC:false`）。

实测（你的实例）：勾上下文模板 → 卡内写入 + 界面立即变；手动把 UI 改回别的值 → 重新进对话自动拉回锁定值；取消锁定 → 卡内 `extra` 清空。

## SPreset 按钮残留（已处理）

SPreset 是**预设自带的插件**（存在 `data.extensions.SPreset` 里），它会往页面插按钮和菜单项，但切到其它预设时从不拆除 → 以前必须刷新。

现在：切到**不带 SPreset 的预设**时，把 SPreset 的入口（`.spreset-button-container`、上传 log 菜单项）隐起来；切回带 SPreset 的预设时自动恢复。不删元素，不破坏它自己的 hook。

实测（你的实例）：

| 切到 | 按钮状态 |
| --- | --- |
| 梦鲸思客V4-1015（无 SPreset） | `display:none` 隐藏 |
| 【小猫之神·喵赛亚】1.6（有 SPreset） | 恢复默认显示 |

## 切换预设后的收尾（不需要刷新页面）

切预设在酒馆里是异步的：`change` 事件只是排队，真正应用在后面的 Promise 里。本扩展切完会做三件事：

1. `await` 酒馆自己的 `getPresetApplicationPromise()`（官方信号，它自己的 `/preset` 后面接 `/api` 也靠这个）
2. 强制重建一次提示词管理器（`sanitizeServiceSettings()` + `render(false)`；酒馆平时只 debounce 重渲染，跨预设时可能来不及）
3. **逐项核对**：把活着的设置与预设定义（`openai_settings[名字]`）逐个字段比。不一样就重放一次 `change` 让它自己重算；还有差就在控制台列出字段名

实测（你的实例，ST 1.19.0）：进入绑定卡的自动切换后，与预设定义对比 **0 项不一致**、67 个提示词内容全一致、`prompt_order` 一致。

控制台出现 `仍有 N 项与预设定义不同` 时，把打印出来的字段名发我——那才是真正残留的东西（插件动态内容不算，已排除 `prompts` / `prompt_order` / `extensions` / 代理字段）。

## 性能

实测数据（浏览器内编号计数，不是估算）：

| 场景 | 20 秒内 DOM 查找 | 请求 |
| --- | --- | --- |
| 角色面板关着 | **0** | 0 |
| 角色面板开着 | 70（≈70 次/20s） | 0（列表 60 秒缓存） |
| 标签页在后台 | 0 | 0 |

怎么做到的：

- 用 MutationObserver 盯面板的 class，面板一关就 `clearInterval`，没有空转定时器
- 巡检 2 秒一次，但内容签名没变就不碰 DOM；列表 60 秒才重拉一次，新增/删除靠 `WORLDINFO_UPDATED` 事件立即刷
- `world-info.js` 只动态 import 一次（之前每次同步都 import）
- `document.hidden` 为真时直接 return

两行标题后面会显示版本号（如 `v1.6.0`）。看不到就是浏览器还在用旧文件，`Ctrl+Shift+R` 硬刷新，或在 DevTools 里勾上 Disable cache 再刷。

### 删卡连带删世界书

在酒馆正常删卡（角色面板 → 更多… → 删除）时：

1. 你先看到酒馆自己的「删除角色？」确认框
2. 点确定后，本扩展弹第二个框，**一次列出**这张卡绑的、可以一并删的世界书
3. 选「一并删除」→ 卡删掉，这些世界书文件也从服务器移除；选「只删角色卡」→ 全部保留

两条安全线：

- **还被其他卡引用的世界书不列入**，只提示保留了
- 只删你确认过的那一次；确认框被关掉/跳过时不会删

开关在**魔杖 → 预设锁定 → 删角色卡时，一并删除它绑定的世界书**（默认开）。

删掉文件后会立即调用酒馆的 `updateWorldInfoList()` 刷新世界书面板，不需要手动刷新页面。
（旧版本遗漏了这一步，会留下一个点了没反应、删也删不掉的幽灵条目——服务端返回 500。）

## 记录存在哪

**主记录：角色卡内**，写在卡文件的 `data.extensions.presetLocks`，形如 `{ preset: "我的预设", at: 1730000000000 }`。

- 走酒馆自带的 `POST /api/characters/merge-attributes`，服务端只做深度合并这一个子键，卡的其它字段不动，写入是原子的
- 它和酒馆自己存 `fav` / `world` / `depth_prompt` 用的是同一套机制，符合角色卡 V2/V3 规范

**兜底记录：本机**，`extension_settings.PresetLocks.characterLocks`（即 `settings.json`），按角色卡的 `avatar` 文件名索引。

- 只在卡内没有记录时生效
- 写入被服务端拒绝时（无写权限、旧版酒馆没有该接口）自动落到这里，功能照旧，提示会说明

## 旧消息的显示（实测结论）

- 切预设时酒馆会发「重新加载聊天以使正则生效」提示。本扩展自动切换时会拦掉它。
- 实测：**点卡进入时切换发生在旧消息渲染之前**，进入后的旧消息直接按新预设渲染正确（用含 <think_nya~> 的测试聊天验证：进入后即显示折叠块，无需重载）。
- 只有在聊天已显示在屏幕上、再手动切预设时，旧消息才保持旧渲染——这是酒馆本身的行为，与本扩展无关。
- 因为「切换」与「首屏渲染」谁先谁后不稳定，面板提供「切换后重绘旧消息」开关，默认**开**：只在目标预设带显示型正则且聊天非空时，切换后自动重绘一次（重读聊天文件，不会丢消息）。

## 已知限制

- 云酒馆/服务器需要允许写角色卡（能编辑角色就能写）。写不进去时提示会说明，并退回本机记录
- 下拉定位靠酒馆的 `#spoiler_free_desc` / `#descriptionWrapper`，如果版本改版导致找不到，这一行不会出现
- 记录跟着**卡文件**走：删卡重导成新文件名，旧记录失效，需要重新绑
- 世界书改了文件名（重命名）后，卡内绑定不会自动跟着改，需要在面板里重选一次
- 世界书文件若被其他途径先删了，删卡时不会报错，只是没有可删的文件
- 绑定的预设若被删除或改名，下拉里仍会列出来（避免静默丢绑定），切换时提示「预设不存在」并保持原样
- 只在**切换角色 / 加载聊天**时检查一次。同一聊天内手动改预设不会被抢回，也不会被记住
- 卡内的预设名写的是你自己酒馆里的名字，把卡分享给别人时对方会看到「预设不存在」
- 与酒馆自带的 `bind_preset_to_connection`（绑定预设到连接）功能重叠。两者都写同一个预设选择框，若出现"切到错的预设"，先关掉那个

## 开发

`_test/` 里是离线逻辑测试，把 `index.js` 的 SillyTavern 导入换成桩件后直接跑真实代码：

```bash
cd _test
node build.js   # 生成 pl.mjs
node run.mjs    # 46 项断言
```

覆盖：卡内写入、卡内优先、本机兜底、写卡失败降级、明确清除不被兜底复活、群聊跳过、预设不存在、角色改名、旧版记录迁移、角色卡界面下拉的渲染与写入、`characterId` 字符串、三种预设下拉来源形态、世界书绑定与删卡连带删除的各条安全分支。

`_test/live-check.sh` / `_test/live-world-fixture.sh` 是在服务器本机验证真实接口的脚本（需要 curl + node）。
