# 预设锁定 · ST-PresetLocks

两件事，都在**角色卡管理界面**里做：

1. 给这张卡绑一个**预设**——同一张卡的所有聊天共用一个预设，切角色时自动换回
2. 给这张卡绑一本**世界书**——随卡自动生效，删卡时可选择一并删除世界书文件

两个绑定都写在**角色卡自己身上**（`data.extensions.presetLocks` / `data.extensions.world`），卡导出、上传、换酒馆时一起走。

中文精简版，基于 [Character Locks v4.0.0](https://github.com/aikohanasaki/SillyTavern-CharacterLocks)（aikohanasaki，AGPL-3.0）重做，只保留角色卡级锁定。

## 安装

解压或复制到酒馆的第三方扩展目录：

```text
SillyTavern/public/scripts/extensions/third-party/ST-PresetLocks/
```

或者从 GitHub 安装：扩展面板 → Install extension → `https://github.com/stttwq/ST-PresetLocks`

重启酒馆，刷新页面。

## 兼容性

在真实运行的 **SillyTavern 1.19.0** 上验证过：卡内写入（`/api/characters/merge-attributes` 返回 200）、面板下拉、切角色自动换预设。

版本差异已适配两处：

- `ctx.characterId` 在 1.19 是字符串（`"40"`），旧版本是数字
- `presetManager.select` 是 jQuery 对象；旧版本可能是选择器字符串

## 怎么用

1. 点左上角 ☰ 打开**角色卡管理界面**
2. 在「标签」下面、「创作者的注释」上面有两行：
   - **🔒 预设锁定**：选一个预设，选完立刻生效并写进这张卡
   - **🌍 世界书锁定（可多选）**：勾一本或多本，勾选顺序就是加载顺序
3. 选完立刻生效，并写进这张卡

之后切到这张卡（任何聊天文件），预设都会自动变成绑定的那个。

## 世界书绑定（可多本）

面板里那行是**复选框列表**，勾几本都行，序号就是加载顺序（1 会写进酒馆原生的 `data.extensions.world`，其余进 `worldBooks` 并在打开卡时同步给酒馆的「角色世界书」`world_info.charLore`）。

因为走的是酒馆自己的**角色世界书**机制，所以：

- 打开/切到这张卡 → 绑定的世界书自动生效，不需要在全局世界书里勾选（可以一本全局都不开）
- **不会污染其他角色**：什么都不全局启用，离开这张卡它就不生效了；切回来又自动恢复
- 左侧列表会标状态：`2 本生效中（序号即加载顺序） · N 本被其他卡共用，删卡时保留`

### 一个坑（已处理）

酒馆模块内部的 `world_info` 和 `extension_settings.world_info` **不是同一个对象**。只写后者，界面上看得见但扫描时根本不生效；只写前者，当下生效但刷新就没了。所以两处都会写。

## 性能

- 角色面板关着时：**零请求**，巡检直接 return
- 面板开着时：世界书列表 60 秒最多重拉一次（新增/删除世界书靠 `WORLDINFO_UPDATED` 事件立即刷新，不等缓存）
- DOM 按签名对比，内容没变不重建
- 切卡/换聊天时才做一次角色世界书同步，且值没变不落盘

### 删卡连带删世界书

在酒馆正常删卡（角色面板 → 更多… → 删除）时：

1. 你先看到酒馆自己的「删除角色？」确认框
2. 点确定后，本扩展弹第二个框，**一次列出**这张卡绑的、可以一并删的世界书
3. 选「一并删除」→ 卡删掉，这些世界书文件也从服务器移除；选「只删角色卡」→ 全部保留

两条安全线：

- **还被其他卡引用的世界书不列入**，只提示保留了
- 只删你确认过的那一次；确认框被关掉/跳过时不会删

开关在**魔杖 → 预设锁定 → 删角色卡时，一并删除它绑定的世界书**（默认开）。

删掉文件后会立即调用酒馆的 `updateWorldInfoList()` 刷新世界书面板，不需要手动刷新页面。
（旧版本遗漏了这一步，会留下一个点了没反应、删也删不掉的幽灵条目——服务端返回 500。）

## 自动切换的三档

档位在**魔杖菜单 → 预设锁定**里设（那一页只放开关和「立即应用」，绑定点在上面那个下拉里）。

| 档位 | 行为 |
| --- | --- |
| 不动预设 | 只在你点「▶ 立即应用」时换 |
| 先问我 | 切角色时弹窗确认，显示要从什么换成什么 |
| 直接换成绑定的预设 | 不问，静默换（**默认**） |

## 记录存在哪

**主记录：角色卡内**，写在卡文件的 `data.extensions.presetLocks`，形如 `{ preset: "我的预设", at: 1730000000000 }`。

- 走酒馆自带的 `POST /api/characters/merge-attributes`，服务端只做深度合并这一个子键，卡的其它字段不动，写入是原子的
- 它和酒馆自己存 `fav` / `world` / `depth_prompt` 用的是同一套机制，符合角色卡 V2/V3 规范

**兜底记录：本机**，`extension_settings.PresetLocks.characterLocks`（即 `settings.json`），按角色卡的 `avatar` 文件名索引。

- 只在卡内没有记录时生效
- 写入被服务端拒绝时（无写权限、旧版酒馆没有该接口）自动落到这里，功能照旧，提示会说明

## 已知限制

- 云酒馆/服务器需要允许写角色卡（能编辑角色就能写）。写不进去时提示会说明，并退回本机记录
- 下拉定位靠酒馆的 `#spoiler_free_desc` / `#descriptionWrapper`，如果版本改版导致找不到，这一行不会出现
- 记录跟着**卡文件**走：删卡重导成新文件名，旧记录失效，需要重新绑
- 世界书改了文件名（重命名）后，卡内绑定不会自动跟着改，需要在面板里重选一次
- 世界书文件若被其他途径先删了，删卡时不会报错，只是没有可删的文件
- 绑定的预设若被删除或改名，下拉里仍会列出来（避免静默丢绑定），切换时提示「预设不存在」并保持原样
- 只在**切换角色 / 加载聊天**时检查一次。同一聊天内手动改预设不会被抢回，也不会被记住
- 卡内的预设名写的是你自己酒馆里的名字，把卡分享给别人时对方会看到「预设不存在」
- 与酒馆自带的 `bind_preset_to_connection`（绑定预设到连接）功能重叠。两者都写同一个预设选择框，若出现"切到错的预设"，先关掉那个

## 开发

`_test/` 里是离线逻辑测试，把 `index.js` 的 SillyTavern 导入换成桩件后直接跑真实代码：

```bash
cd _test
node build.js   # 生成 pl.mjs
node run.mjs    # 58 项断言
```

覆盖：卡内写入、卡内优先、本机兜底、写卡失败降级、明确清除不被兜底复活、群聊跳过、预设不存在、角色改名、旧版记录迁移、角色卡界面下拉的渲染与写入、`characterId` 字符串、三种预设下拉来源形态、世界书绑定与删卡连带删除的各条安全分支。

`_test/live-check.sh` / `_test/live-world-fixture.sh` 是在服务器本机验证真实接口的脚本（需要 curl + node）。
